# arch.serve.gateway：模型服务网关

## 0. 一句话直觉

**模型服务网关（Gateway）是客户端与模型服务之间的“统一入口 + 交通警察”**：它接收所有推理请求，做鉴权、限流、路由、日志、协议转换，再把请求转发给后端真正干活的模型服务。没有它，每接一个新模型客户端都要改地址、改鉴权、改超时逻辑——这正是工程级 AI 系统最先崩溃的地方。

---

## 1. 为什么需要网关：从“直连模型”说起

零基础时，我们常这样调模型：

```python
# 教科书写法：客户端直接调用模型
import requests

resp = requests.post("http://model-server:8000/predict", json={"text": "hello"})
print(resp.json())
```

问题在于，一旦模型变多、客户端变多，就会爆炸：

- 每个模型一个地址，客户端要维护一张地址表；
- 鉴权逻辑散落在各个服务，改一次全都要动；
- 某个模型被打爆，其他模型也跟着挂；
- 没法统一记日志、统计 QPS（Queries Per Second，每秒查询数）。

**网关的核心思想**：客户端只认识一个地址，其他都由网关内部处理。

```python
# 网关思想：客户端只需要认识一个地址
# 客户端不再直连 model-a、model-b，而是统一打到 gateway
GATEWAY_URL = "http://gateway:9000/v1/infer"

payload = {
    "model": "sentiment",          # 路由信息：网关据此决定转发给谁
    "input": "I love Python",
}
# 客户端只发一次请求，鉴权、限流、路由、日志全在网关内部完成
```

## 2. 网关的四大核心职责

| 职责 | 英文 | 作用 |
|---|---|---|
| 路由 | Routing | 根据 model 字段决定请求转发到哪个后端 |
| 鉴权 | Authentication | 校验 API Key / Token，拒绝非法请求 |
| 限流 | Rate Limiting | 控制单用户/全局 QPS，防止雪崩 |
| 可观测 | Observability | 统一日志、指标（Metrics）、追踪（Tracing） |

下面用一段可运行的代码模拟这四个职责。

```python
# demo_gateway.py —— 一个最小可运行的网关原型
import time
from collections import defaultdict

# 1) 路由表：模型名 -> 后端地址
ROUTES = {
    "sentiment": "http://model-sentiment:8001/predict",
    "embedding": "http://model-embedding:8002/predict",
}

# 2) 合法 API Key（生产环境应查数据库或配置中心）
VALID_KEYS = {"sk-alice": 5, "sk-bob": 2}  # key -> 每秒允许的 QPS

# 3) 简单限流器：记录每个 key 在当前秒的调用次数
_counter = defaultdict(int)
_window_start = time.time()


def gateway_handle(api_key: str, model: str, payload: dict):
    global _window_start, _counter

    # --- 鉴权 ---
    if api_key not in VALID_KEYS:
        return {"code": 401, "msg": "invalid api key"}

    # --- 路由 ---
    if model not in ROUTES:
        return {"code": 404, "msg": f"unknown model: {model}"}

    # --- 限流（按秒切窗口） ---
    now = time.time()
    if now - _window_start >= 1.0:
        _window_start = now
        _counter.clear()
    limit = VALID_KEYS[api_key]
    if _counter[api_key] >= limit:
        return {"code": 429, "msg": "rate limit exceeded"}
    _counter[api_key] += 1

    # --- 转发（此处用 mock 代替真实 HTTP 调用） ---
    backend = ROUTES[model]
    # 真实场景：用 httpx.post(backend, json=payload)
    fake_response = {"model": model, "output": f"processed:{payload['input']}"}

    # --- 可观测：打印结构化日志 ---
    print(f"[LOG] key={api_key} model={model} backend={backend}")
    return {"code": 200, "data": fake_response}


if __name__ == "__main__":
    print(gateway_handle("sk-alice", "sentiment", {"input": "hi"}))
    print(gateway_handle("sk-bob",   "embedding", {"input": "hi"}))
    print(gateway_handle("sk-bad",   "sentiment", {"input": "hi"}))
    # 触发限流：bob 的 QPS=2，第三次会被拒绝
    print(gateway_handle("sk-bob",   "embedding", {"input": "again"}))
    print(gateway_handle("sk-bob",   "embedding", {"input": "again"}))
```

运行它会依次看到 200 / 200 / 401 / 200 / 429。这就是网关在真实系统里的行为缩影。

## 3. 工程级网关的典型形态

生产环境一般不会手写上面那种代码，而是选择成熟组件：

- **Nginx / Envoy / Traefik**：通用反向代理（Reverse Proxy），负责 L7 路由、TLS、限流。
- **Kong / APISIX**：API 网关，插件化支持鉴权、限流、熔断（Circuit Breaking）。
- **自定义 FastAPI 网关**：AI 场景常需要自定义逻辑，比如按 token 计费、拼接 prompt、模型 A/B 测试。

一个典型的部署拓扑：

```
Client → [ Gateway ] → [ Model Service A ]
                    → [ Model Service B ]
                    → [ Model Service C ]
```

关键设计点：

1. **无状态（Stateless）**：网关本身不存会话，方便水平扩容。
2. **健康检查（Health Check）**：后端挂了自动摘除。
3. **超时与重试（Timeout / Retry）**：避免请求卡死。
4. **协议转换**：对外 REST，对内有 gRPC（Google Remote Procedure Call）。

下面演示“健康检查 + 自动摘除”的核心逻辑。

```python
# health_check_demo.py —— 后端健康检查与故障摘除
import random

backends = {
    "model-a": {"url": "http://a:8000", "healthy": True},
    "model-b": {"url": "http://b:8000", "healthy": True},
    "model-c": {"url": "http://c:8000", "healthy": True},
}


def probe(name: str) -> bool:
    """模拟健康探测：真实场景是发 /health 请求"""
    return random.random() > 0.3  # 70% 概率健康


def refresh_health():
    for name in backends:
        backends[name]["healthy"] = probe(name)
    print("health:", {k: v["healthy"] for k, v in backends.items()})


def pick_backend():
    """只从健康后端里选一个"""
    healthy = [n for n, v in backends.items() if v["healthy"]]
    if not healthy:
        raise RuntimeError("no healthy backend")
    return random.choice(healthy)


if __name__ == "__main__":
    refresh_health()
    for _ in range(5):
        print("routed to:", pick_backend())
```

## 4. 网关与 Python 类型系统的联动

写网关时，请求/响应的结构必须可预测。Python 的 `typing` 提供了强力工具，让你在编译期就能发现 schema 不一致。

### 4.1 `Self`：让返回类型随子类变化

网关里常有基类 `BaseHandler`，子类各自实现 `handle`，希望返回值仍是子类类型（比如做链式调用）。

```python
from typing import Self

class BaseHandler:
    def with_timeout(self, seconds: int) -> Self:
        self.timeout = seconds
        return self  # 返回 self，用 Self 标注，子类调用后类型仍是子类

class InferHandler(BaseHandler):
    pass

h = InferHandler().with_timeout(3)  # h 的类型被推断为 InferHandler，而不是 BaseHandler
```

用 `Self` 而不是写死 `BaseHandler`，子类链式调用就不会丢失类型信息。PEP 673，Python 3.11 加入。

### 4.2 `TypeAlias`：给复杂类型起个名字

网关里经常出现 `list[int]`、`dict[str, str]` 这种复杂类型，重复写很啰嗦。

```python
from typing import TypeAlias

Headers: TypeAlias = dict[str, str]
QueryParams: TypeAlias = dict[str, str]

# 现在函数签名清晰多了
def route(path: str, headers: Headers, params: QueryParams) -> str:
    return f"routing {path} with {len(headers)} headers"
```

`TypeAlias` 在旧版本 Python 上还能帮忙处理前向引用（Forward Reference）。PEP 613，Python 3.10 加入；3.12 起推荐用 `type` 语句替代。

### 4.3 `TypeVar`：泛型的基石

网关的“后端选择器”可能对任意请求/响应类型都通用。

```python
from typing import TypeVar

T = TypeVar("T")

def first_or_default(items: list[T], default: T) -> T:
    return items[0] if items else default

# 传入 list[str] 时返回 str，传入 list[int] 时返回 int，类型检查器都能推出来
```

`TypeVar` 支持上界（bound）与约束（constraints），是写可复用网关组件的核心工具。

## 5. 小结

- 网关是 AI 服务的统一入口，承担 **路由 / 鉴权 / 限流 / 可观测** 四大职责。
- 生产环境优先选择 Nginx、Kong、APISIX 等成熟组件，AI 场景可叠加自定义 FastAPI 网关。
- 设计要点：无状态、健康检查、超时重试、协议转换。
- 用 `Self`、`TypeAlias`、`TypeVar` 让网关代码在类型层面也稳固可靠。

```python
# full_gateway_demo.py —— 网关完整可运行示例
# 运行：python full_gateway_demo.py
import time
from collections import defaultdict
from typing import Self, TypeAlias

# ---------- 类型别名 ----------
Headers: TypeAlias = dict[str, str]
Payload: TypeAlias = dict[str, str]


# ---------- 后端定义：用 Self 支持链式配置 ----------
class Backend:
    def __init__(self, name: str, url: str) -> None:
        self.name = name
        self.url = url
        self.timeout = 5
        self.healthy = True

    def with_timeout(self, seconds: int) -> Self:
        self.timeout = seconds
        return self  # 返回 self，用 Self 标注，方便链式调用

    def mark_unhealthy(self) -> None:
        self.healthy = False


# ---------- 网关核心 ----------
class Gateway:
    def __init__(self, routes: dict[str, Backend], keys: dict[str, int]) -> None:
        self.routes = routes          # model -> Backend
        self.keys = keys              # api_key -> 每秒 QPS 上限
        self._counter: dict[str, int] = defaultdict(int)
        self._window_start = time.time()

    def _check_rate(self, key: str) -> bool:
        now = time.time()
        if now - self._window_start >= 1.0:
            self._window_start = now
            self._counter.clear()
        if self._counter[key] >= self.keys[key]:
            return False
        self._counter[key] += 1
        return True

    def handle(self, key: str, model: str, payload: Payload,
               headers: Headers | None = None) -> dict:
        # 鉴权
        if key not in self.keys:
            return {"code": 401, "msg": "invalid key"}
        # 路由
        backend = self.routes.get(model)
        if backend is None or not backend.healthy:
            return {"code": 503, "msg": "no healthy backend"}
        # 限流
        if not self._check_rate(key):
            return {"code": 429, "msg": "rate limited"}
        # 转发（mock）
        print(f"[LOG] key={key} model={model} -> {backend.url} "
              f"timeout={backend.timeout} headers={headers}")
        return {"code": 200, "data": {"model": model,
                                       "output": payload.get("input", "").upper()}}


if __name__ == "__main__":
    # 用 Self 链式配置后端
    routes = {
        "sentiment": Backend("sentiment", "http://a:8000").with_timeout(3),
        "embedding": Backend("embedding", "http://b:8000").with_timeout(10),
    }
    gw = Gateway(routes, keys={"sk-alice": 5, "sk-bob": 1})

    print(gw.handle("sk-alice", "sentiment", {"input": "hello"}))
    print(gw.handle("sk-bob",   "embedding", {"input": "hi"}))
    print(gw.handle("sk-bob",   "embedding", {"input": "again"}))  # 429
    print(gw.handle("sk-bad",   "sentiment", {"input": "x"}))     # 401

    routes["sentiment"].mark_unhealthy()
    print(gw.handle("sk-alice", "sentiment", {"input": "y"}))      # 503
```

## arch.serve.router

# arch.serve.router：从零理解服务路由

## 一句话直觉

**路由（router）** 就是服务的“前台分诊台”：它根据请求里的信息，把请求交给正确的处理函数（handler），让你不用写一堆 `if/elif` 去判断“这个请求到底该谁处理”。

在 Python 后端里，路由通常是“URL 路径 → 函数”的映射；但它也可以按方法、主机头、版本号等条件分发。学它的价值是：让服务从“能跑”走向“可维护、可扩展、可测试”。

---

## 1. 最小路由：用字典把路径映射到函数

**分诊台**最朴素的实现就是一个字典：键是路径，值是函数。

关键结论：路由的核心是“匹配 + 调用”。匹配靠查找，调用靠 Python 的可调用对象（callable）。

```python
# 最小路由：字典映射
routes = {}

def route(path):
    def decorator(func):
        routes[path] = func
        return func
    return decorator

@route("/")
def home():
    return "home page"

@route("/hello")
def hello():
    return "hello world"

def dispatch(path):
    handler = routes.get(path)
    if handler is None:
        return "404 Not Found"
    return handler()

print(dispatch("/"))      # home page
print(dispatch("/hello")) # hello world
print(dispatch("/nope"))  # 404 Not Found
```

---

## 2. 带参数的路径：从静态匹配到动态匹配

真实服务的 URL 常带参数，如 `/users/42`。我们需要把 `42` 提取出来传给处理函数。

关键结论：动态路由需要“模式匹配”。在 Python 里可以用正则表达式（regex）或字符串分割实现；工程框架会进一步编译路径模板以提升性能。

```python
import re

class Router:
    def __init__(self):
        self.routes = []  # (compiled_regex, handler)

    def add(self, pattern, handler):
        # 把 /users/{id} 转成正则 /users/(?P<id>[^/]+)
        regex = re.sub(r"\{(\w+)\}", r"(?P<\1>[^/]+)", pattern)
        self.routes.append((re.compile(f"^{regex}$"), handler))

    def dispatch(self, path):
        for regex, handler in self.routes:
            m = regex.match(path)
            if m:
                return handler(**m.groupdict())
        return "404 Not Found"

r = Router()
r.add("/users/{id}", lambda id: f"user id = {id}")
r.add("/posts/{slug}", lambda slug: f"post slug = {slug}")

print(r.dispatch("/users/42"))     # user id = 42
print(r.dispatch("/posts/abc"))    # post slug = abc
print(r.dispatch("/nope"))         # 404 Not Found
```

## 3. 方法分发：同一路径，不同 HTTP 方法

REST（Representational State Transfer）风格里，`GET /users/1` 和 `DELETE /users/1` 是不同操作。

关键结论：路由的键不只是路径，还应包含 HTTP 方法（method）。

```python
class MethodRouter:
    def __init__(self):
        self.routes = {}  # (method, path) -> handler

    def add(self, method, path, handler):
        self.routes[(method.upper(), path)] = handler

    def dispatch(self, method, path):
        key = (method.upper(), path)
        handler = self.routes.get(key)
        if handler is None:
            return "404 Not Found"
        return handler()

mr = MethodRouter()
mr.add("GET", "/users/1", lambda: "get user 1")
mr.add("DELETE", "/users/1", lambda: "delete user 1")

print(mr.dispatch("GET", "/users/1"))     # get user 1
print(mr.dispatch("DELETE", "/users/1"))  # delete user 1
print(mr.dispatch("POST", "/users/1"))    # 404 Not Found
```

## 4. 路由的工程化关注点：优先级、中间件、性能

当路由变多，你需要关注：

- **优先级**：静态路径 `/users/me` 应优先于动态路径 `/users/{id}`，否则 `me` 会被当成 id。
- **中间件（middleware）**：日志、鉴权、限流等横切逻辑，可以在匹配前后插入。
- **性能**：路由表不宜线性扫描。生产框架会用前缀树（trie）或哈希 + 分段匹配来接近 O(1)。

```python
# 优先级：静态优先
class PriorityRouter:
    def __init__(self):
        self.static = {}
        self.dynamic = []

    def add_static(self, path, handler):
        self.static[path] = handler

    def add_dynamic(self, compiled_regex, handler):
        self.dynamic.append((compiled_regex, handler))

    def dispatch(self, path):
        if path in self.static:          # 先查静态
            return self.static[path]()
        for regex, handler in self.dynamic:  # 再查动态
            m = regex.match(path)
            if m:
                return handler(**m.groupdict())
        return "404 Not Found"

pr = PriorityRouter()
pr.add_static("/users/me", lambda: "current user")
pr.add_dynamic(re.compile(r"^/users/(?P<id>[^/]+)$"), lambda id: f"user {id}")

print(pr.dispatch("/users/me"))  # current user
print(pr.dispatch("/users/42"))  # user 42
```

## 5. 与类型系统的关系：`Self`、`TypeVar`、`TypeAlias` 在路由库中的用法

写路由库时，你常会遇到“返回 self”“泛型 handler”“类型别名”等场景。权威源材料给出了明确指导：

- **`Self`**：当方法保证返回“当前子类实例”时，用 `Self` 而不是写死类名。例如路由装饰器返回原函数、`__enter__` 返回 self。
- **`TypeVar`**：用于泛型 handler 或泛型路由容器，让类型检查器能推导具体类型。
- **`TypeAlias`**：给复杂类型起别名。Python 3.12 起推荐改用 `type` 语句，`TypeAlias` 已被弃用但仍可用。

```python
from typing import Self, TypeVar, Callable, TypeAlias

Handler = TypeAlias = Callable[..., str]  # 类型别名
T = TypeVar("T")

class Route:
    def __init__(self, path: str, handler: Handler):
        self.path = path
        self.handler = handler

    def with_handler(self, handler: Handler) -> Self:
        # 返回 Self，子类调用时仍推导为子类类型
        self.handler = handler
        return self

class LoggedRoute(Route):
    pass

r = LoggedRoute("/", lambda: "hi").with_handler(lambda: "new")
print(r.handler())  # new
```

**权威源材料要点回顾**：
- `Self` 用于返回 self 的方法、替代构造器（classmethod）、`__enter__`；若总是返回固定类实例（如 `Eggs()`），则不能用 `Self`。
- `TypeAlias` 用于显式声明类型别名，尤其处理前向引用；3.12 起推荐 `type` 语句。
- `TypeVar` 支持有界（bound）与约束（constraints），有界取最具体类型，约束只能取给定集合之一。

## 动手练习

实现一个 `MiniRouter` 类，满足：

1. 支持 `add(method, path, handler)`，其中 `path` 可含 `{name}` 占位符。
2. 支持 `dispatch(method, path)`，返回 handler 的调用结果或 `404 Not Found`。
3. 静态路径优先于动态路径。
4. 用 `typing` 给 `add` 和 `dispatch` 加类型标注，handler 类型用 `Callable[..., str]`。
5. 写至少 3 条测试：静态命中、动态命中、404。

提示：可参考第 4 节 `PriorityRouter` 的结构，把 method 也纳入键。

```python
import re
from typing import Callable, TypeAlias

Handler: TypeAlias = Callable[..., str]

class MiniRouter:
    def __init__(self):
        self.static = {}   # (method, path) -> handler
        self.dynamic = []  # (method, compiled_regex, handler)

    def add(self, method: str, path: str, handler: Handler) -> None:
        method = method.upper()
        if "{" in path:
            regex = re.sub(r"\{(\w+)\}", r"(?P<\1>[^/]+)", path)
            self.dynamic.append((method, re.compile(f"^{regex}$"), handler))
        else:
            self.static[(method, path)] = handler

    def dispatch(self, method: str, path: str) -> str:
        method = method.upper()
        if (method, path) in self.static:
            return self.static[(method, path)]()
        for m, regex, handler in self.dynamic:
            if m != method:
                continue
            match = regex.match(path)
            if match:
                return handler(**match.groupdict())
        return "404 Not Found"

# 使用示例
r = MiniRouter()
r.add("GET", "/users/me", lambda: "current user")
r.add("GET", "/users/{id}", lambda id: f"user {id}")
r.add("DELETE", "/users/{id}", lambda id: f"deleted {id}")

print(r.dispatch("GET", "/users/me"))      # current user
print(r.dispatch("GET", "/users/42"))      # user 42
print(r.dispatch("DELETE", "/users/42"))   # deleted 42
print(r.dispatch("POST", "/users/42"))     # 404 Not Found
```
