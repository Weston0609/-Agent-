## agent.llm.function_calling

# agent.llm.function_calling 教学讲义（40 分钟）

## 一句话直觉
**Function Calling（函数调用）** 让大语言模型（LLM，Large Language Model）不再只是"聊天"，而是能主动说"我需要调用哪个函数、传什么参数"，从而把自然语言变成可执行的结构化指令。

---

## 1. 为什么需要 Function Calling？

LLM 本质是一个**文本到文本**的概率模型。你问"北京今天天气怎么样？"，它只能根据训练数据编一个答案，无法真正查询实时数据。

Function Calling 的核心思路：**把"工具"的说明书（schema）交给模型**，模型决定是否调用、调用哪个、参数是什么，然后由你的代码真正执行函数，再把结果喂回模型生成最终回答。

关键角色：
- **Tool / Function**：你能调用的外部能力（查天气、查数据库、发邮件）。
- **Schema**：用 JSON Schema 描述函数的名称、参数、类型。
- **Tool Call**：模型输出的结构化调用请求。
- **Tool Result**：你执行函数后返回给模型的结果。

```python
# 直觉演示：模型不会算实时天气，但能"要求"你调用 get_weather
user = "北京今天天气怎么样？"
# 模型输出（结构化）：
# {"name": "get_weather", "arguments": {"city": "北京"}}
# 你的代码执行 get_weather("北京") -> "晴，25°C"
# 再把结果喂回模型 -> "北京今天晴，气温约 25°C。"
```

---

## 2. 函数定义：用 JSON Schema 描述工具

模型不认识你的 Python 函数，它只认识 **JSON Schema（JSON 模式）**。每个工具需要：
- `name`：函数名（模型会原样返回）。
- `description`：自然语言说明（模型主要靠它判断何时调用）。
- `parameters`：参数的 JSON Schema。

```python
# 定义一个工具的 schema（OpenAI 风格）
weather_tool = {
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查询指定城市的当前天气",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "城市名，如 北京"},
                "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
            },
            "required": ["city"]
        }
    }
}
```

**关键结论**：`description` 写得越清楚，模型选对工具的概率越高。这是"提示词工程"在 Function Calling 里的体现。

---

## 3. 调用流程：一次完整的"请求—执行—回填"

Function Calling 的标准四步循环：

1. 把用户消息 + 工具列表发给模型。
2. 模型返回 `tool_calls`（可能为空，即直接回答）。
3. 你的代码执行对应函数，得到结果。
4. 把结果作为 `tool` 角色消息追加，再次请求模型，得到自然语言答案。

```python
# 伪代码结构（用字典模拟消息）
messages = [{"role": "user", "content": "北京天气？"}]

# 第 1 步：请求模型
# response = client.chat.completions.create(model=..., messages=messages, tools=[weather_tool])
# 第 2 步：模型返回 tool_calls
# tool_call = response.choices[0].message.tool_calls[0]
# 第 3 步：执行本地函数
# result = get_weather(**json.loads(tool_call.function.arguments))
# 第 4 步：把结果回填
# messages.append({"role": "tool", "tool_call_id": tool_call.id, "content": result})
# final = client.chat.completions.create(model=..., messages=messages, tools=[weather_tool])
```

**关键结论**：`tool_call_id` 是模型把"调用请求"和"执行结果"对应起来的钥匙，缺失会导致模型无法继续。

---

## 4. 工程要点：并行调用、错误处理、多个工具

真实场景下模型可能一次返回多个 `tool_calls`（并行调用），也可能调错参数。工程上要处理：

- **并行执行**：多个 tool_call 可以并发执行，再一起回填。
- **错误处理**：函数抛异常时，把错误信息作为 tool result 返回，让模型自己纠错。
- **参数校验**：不要直接 `eval`，用 `json.loads` + 白名单函数映射。
- **循环控制**：设置最大轮数，防止模型反复调用陷入死循环。

```python
# 安全的函数映射表
TOOLS = {"get_weather": get_weather}

def execute_tool_call(tool_call):
    name = tool_call["function"]["name"]
    args = json.loads(tool_call["function"]["arguments"])
    if name not in TOOLS:
        return {"error": f"unknown tool: {name}"}
    try:
        return TOOLS[name](**args)
    except Exception as e:
        return {"error": str(e)}
```

**关键结论**：Function Calling 是"模型决策 + 代码执行"的分工，安全边界必须在你的代码里，而不是依赖模型。

---

## 5. 从 Function Calling 到 Agent

当工具不止一个、需要多轮决策时，Function Calling 就演变成了 **Agent（智能体）** 的核心循环：

```
while not done:
    resp = llm(messages, tools)
    if resp.tool_calls:
        results = [execute(tc) for tc in resp.tool_calls]
        messages += results
    else:
        done = True
```

这就构成了 **ReAct（Reasoning + Acting）** 模式的工程底座。掌握 Function Calling，是理解后续所有 Agent 框架（LangChain、AutoGen、Claude Tool Use）的第一步。

## agent.llm.tool_use

## 一句话直觉
LLM（大语言模型）本身只会“说话”，不会查天气、算账、读文件；**tool use（工具调用）** 就是教它：先决定“该用哪个工具”，再按格式输出参数，由外部程序去执行，最后把结果喂回给模型继续说。

---

## 1. 为什么需要 tool use？

LLM 的本质是“根据上下文预测下一个 token”，它没有实时信息、不能精确计算、也无法直接操作外部系统。

**关键结论**：把 LLM 当作“调度器”而不是“执行器”，让它输出结构化指令，由 Python 代码真正干活。

```python
# 直觉演示：模型自己算不准，但可以“请求”计算器
user_question = "1234 * 5678 等于多少？"

# 模型直接回答（不可靠）
llm_direct_answer = "大约 7006652"  # 可能错

# 模型请求工具（可靠）
tool_call = {"tool": "calculator", "args": {"expression": "1234 * 5678"}}
print(tool_call)
```

---

## 2. 工具调用的最小闭环：四步

一个完整的 tool use 循环（loop）包含：

1. **定义工具**：名称、描述、参数 schema（JSON Schema）。
2. **模型决策**：模型输出“我要调用哪个工具、参数是什么”。
3. **本地执行**：Python 函数真正运行。
4. **结果回填**：把工具输出作为新消息再发给模型。

**关键结论**：工具描述写得越清楚，模型选错工具的概率越低。

```python
import json

# 1) 定义工具（用普通 Python 函数 + 描述）
def get_weather(city: str) -> str:
    """查询指定城市的天气。"""
    fake_db = {"北京": "晴 25°C", "上海": "多云 28°C"}
    return fake_db.get(city, "未知城市")

# 工具 schema，供模型阅读
tools = [{
    "name": "get_weather",
    "description": "查询城市天气",
    "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]
    }
}]
print(json.dumps(tools, ensure_ascii=False, indent=2))
```

## 3. 用伪 LLM 模拟一次完整调用

真实场景里模型会返回 `tool_calls`，这里用规则模拟，方便零基础先跑通流程。

**关键结论**：tool use 的核心不是模型多聪明，而是**消息协议**要闭环。

```python
import json

# 模拟 LLM：看到问题就决定调 get_weather
def fake_llm(messages):
    last = messages[-1]["content"]
    if "天气" in last and "tool_result" not in last:
        return {
            "role": "assistant",
            "tool_calls": [{
                "name": "get_weather",
                "arguments": {"city": "北京"}
            }]
        }
    return {"role": "assistant", "content": f"根据工具结果：{last}"}

# 本地工具注册表
TOOL_REGISTRY = {"get_weather": get_weather}

def run_agent(user_input: str, max_turns: int = 3):
    messages = [{"role": "user", "content": user_input}]
    for _ in range(max_turns):
        reply = fake_llm(messages)
        messages.append(reply)
        if "tool_calls" not in reply:
            return reply["content"]
        for call in reply["tool_calls"]:
            result = TOOL_REGISTRY[call["name"]](**call["arguments"])
            messages.append({
                "role": "tool",
                "name": call["name"],
                "content": json.dumps(result, ensure_ascii=False)
            })
    return "达到最大轮数"

print(run_agent("北京天气怎么样？"))
```

## 4. 工程化要点

- **参数校验**：用 Pydantic（数据校验库）校验模型给的参数。
- **超时与重试**：任何工具都可能失败，必须 try/except。
- **权限隔离**：危险工具（写文件、发邮件）要加白名单。
- **可观测性**：记录每次 tool_call 的输入输出，便于调试。

**关键结论**：生产级 tool use = 模型决策 + 强约束执行 + 可回放日志。

```python
from pydantic import BaseModel, ValidationError

class WeatherArgs(BaseModel):
    city: str

def safe_call(name: str, raw_args: dict):
    try:
        if name == "get_weather":
            args = WeatherArgs(**raw_args)
            return get_weather(args.city)
    except ValidationError as e:
        return f"参数错误: {e}"
    except Exception as e:
        return f"工具异常: {e}"

print(safe_call("get_weather", {"city": "上海"}))
print(safe_call("get_weather", {}))
```

## 5. 与真实 LLM 对接的提示

真实 API（如 OpenAI、Anthropic、通义）都支持 `tools` 字段，返回的 `tool_calls` 结构类似上面模拟。你只需把第 3 节的 `fake_llm` 换成真实 SDK 调用，其余循环逻辑不变。

```python
import json

    # 模拟天气数据库
    fake_db = {"北京": "晴 25°C", "上海": "多云 28°C"}
    return fake_db.get(city, "未知城市")

tools = [{
    "name": "get_weather",
    "description": "查询城市天气",
    "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]
    }
}]

def fake_llm(messages):
    last = messages[-1]["content"]
    if "天气" in last and "tool_result" not in last:
        return {
            "role": "assistant",
            "tool_calls": [{"name": "get_weather", "arguments": {"city": "北京"}}]
        }
    return {"role": "assistant", "content": f"根据工具结果：{last}"}

TOOL_REGISTRY = {"get_weather": get_weather}

def run_agent(user_input: str, max_turns: int = 3):
    messages = [{"role": "user", "content": user_input}]
    for _ in range(max_turns):
        reply = fake_llm(messages)
        messages.append(reply)
        if "tool_calls" not in reply:
            return reply["content"]
        for call in reply["tool_calls"]:
            result = TOOL_REGISTRY[call["name"]](**call["arguments"])
            messages.append({
                "role": "tool",
                "name": call["name"],
                "content": json.dumps(result, ensure_ascii=False)
            })
    return "达到最大轮数"

if __name__ == "__main__":
    print(run_agent("北京天气怎么样？"))
```
