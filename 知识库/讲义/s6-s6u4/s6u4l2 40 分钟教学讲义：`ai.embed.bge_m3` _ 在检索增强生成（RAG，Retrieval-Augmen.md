## ai.embed.bge_m3

# 40 分钟教学讲义：`ai.embed.bge_m3`

## 一句话直觉
**BGE-M3 是一个可以把文本变成“语义向量”（embedding）的多语言、多功能模型；学会它，你就能做搜索、聚类、去重、推荐和 RAG（Retrieval-Augmented Generation，检索增强生成）。**

---

## 第 1 节：什么是 Embedding？为什么 BGE-M3 值得学

### 1.1 从“字面匹配”到“语义匹配”
传统搜索依赖关键词是否出现。问题是：用户搜“如何缓解焦虑”，文章写“减轻紧张情绪的方法”，两者字面不同，但语义接近。

**Embedding（嵌入）** 把一段文本映射成一个固定长度的浮点数向量，例如 1024 维。语义相近的文本，在向量空间里距离更近。

### 1.2 BGE-M3 的三个关键词
- **BGE**：BAAI General Embedding，北京智源研究院推出的通用嵌入模型系列。
- **M3**：Multi-Lingual（多语言）、Multi-Granularity（多粒度，支持短句到长文）、Multi-Functionality（多功能，同时支持稠密检索、稀疏检索、多向量检索）。
- **常用场景**：语义搜索、RAG 召回、文本聚类、去重、分类特征、推荐召回。

### 1.3 为什么它是很好的起点
- 支持 100+ 语言，中英文效果都强。
- 最大输入长度通常为 8192 tokens，适合长文档。
- 输出 1024 维向量，工程上容易存储和检索。
- 开源，可本地部署，也可通过 API 调用。

---

## 第 2 节：BGE-M3 的输出是什么？稠密、稀疏、多向量

BGE-M3 的“多功能”体现在它不只是一个向量：

1. **Dense Embedding（稠密向量）**
   - 每个文本变成一个 1024 维向量。
   - 用余弦相似度（Cosine Similarity）比较。
   - 适合语义召回。

2. **Sparse Embedding（稀疏向量）**
   - 类似 BM25 的词权重表示，强调关键词匹配。
   - 适合精确术语、专有名词召回。

3. **ColBERT-style Multi-Vector（多向量）**
   - 每个 token 保留一个向量，做 late interaction（后交互）匹配。
   - 精度高，但存储和计算更贵。

工程上最常见的是：**先用稠密向量做召回，再用稀疏或多向量做重排**。

## 第 3 节：最小可运行示例：把文本变成向量

下面代码使用 `sentence-transformers` 加载 BGE-M3。首次运行会下载模型，请确保网络可用。

```python
# 安装依赖：
# pip install -U sentence-transformers numpy

from sentence_transformers import SentenceTransformer
import numpy as np

# 1. 加载 BGE-M3 模型
# 模型名称：BAAI/bge-m3
model = SentenceTransformer("BAAI/bge-m3")

# 2. 准备文本
sentences = [
    "如何缓解焦虑情绪",
    "减轻紧张和压力的方法",
    "今天天气很好，适合跑步",
]

# 3. 生成稠密向量
# normalize_embeddings=True 让向量长度为 1，后续可直接点积算余弦相似度
embeddings = model.encode(sentences, normalize_embeddings=True)

print("向量形状:", embeddings.shape)  # (3, 1024)

# 4. 计算两两余弦相似度
sim_matrix = embeddings @ embeddings.T
print("相似度矩阵:\n", np.round(sim_matrix, 4))

# 预期：第 1 句和第 2 句相似度高，和第 3 句相似度低
```

### 关键结论
- `encode` 返回的是 `numpy.ndarray` 或 `torch.Tensor`，形状为 `(文本数, 向量维度)`。
- 设置 `normalize_embeddings=True` 后，余弦相似度就等于点积。
- 相似度越接近 1，语义越接近。

## 第 4 节：工程级用法：批量编码、长文本与检索

### 4.1 批量编码与 GPU
真实系统里文本很多，必须批量处理。

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-m3", device="cuda")  # 没有 GPU 就删掉 device

texts = [f"这是第 {i} 条测试文本，用于演示批量编码。" for i in range(1000)]

# batch_size 控制显存占用；show_progress_bar 方便观察进度
embeddings = model.encode(
    texts,
    batch_size=32,
    normalize_embeddings=True,
    show_progress_bar=True,
)

print(embeddings.shape)  # (1000, 1024)
```

### 4.2 长文本处理
BGE-M3 最大长度通常为 8192 tokens，但过长文本会：
- 增加显存/内存。
- 稀释语义，导致检索不精准。

常见策略：
- **切块（chunking）**：按段落或固定长度切分，分别编码。
- **聚合**：对 chunk 向量取平均，或保留多个 chunk 向量分别检索。

```python
# 简单按长度切块示例
def chunk_text(text: str, chunk_size: int = 500, overlap: int = 50):
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start = end - overlap
    return chunks

long_doc = "这是一篇很长的文档。" * 300
chunks = chunk_text(long_doc)
chunk_embs = model.encode(chunks, normalize_embeddings=True, batch_size=16)
print(len(chunks), chunk_embs.shape)
```

### 4.3 一个最小语义检索流程
```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("BAAI/bge-m3")

# 文档库
docs = [
    "Python 是一种解释型、面向对象的编程语言。",
    "BGE-M3 支持多语言文本嵌入。",
    "今天股市大涨，科技板块领涨。",
]
doc_embs = model.encode(docs, normalize_embeddings=True)

# 查询
query = "多语言向量模型"
q_emb = model.encode(query, normalize_embeddings=True)

# 余弦相似度排序
scores = doc_embs @ q_emb
rank = np.argsort(-scores)

for i in rank:
    print(f"分数={scores[i]:.4f}  文档={docs[i]}")
```

## 第 5 节：常见工程选择与注意事项

| 问题 | 建议 |
|---|---|
| 用哪种向量？ | 一般先用 dense；关键词强的场景加 sparse；精度要求高再加 multi-vector。 |
| 是否归一化？ | 用余弦相似度时建议 `normalize_embeddings=True`。 |
| 维度太高？ | 可以用 PCA、UMAP 或 Matryoshka 思路降维，但会损失精度。 |
| 中文任务？ | BGE-M3 中文效果通常优于多数通用模型。 |
| 存储？ | 100 万条 1024 维 float32 约 4GB，可用 FAISS、Milvus、Qdrant 等向量库。 |
| 模型下载慢？ | 可配置 Hugging Face 镜像或提前下载到本地。 |

## ai.embed.reranker

## 一句话直觉

**重排序器（Reranker）** 是检索系统里的“精读裁判”：先用便宜又快的方式粗筛出一小批候选，再让一个更贵但更准的模型逐条精读并重新打分排序，让真正相关的答案排到最前面。

---

## 1. 为什么需要 Reranker？

在检索增强生成（RAG，Retrieval-Augmented Generation）里，常见流程是：

1. 把文档切块（chunk）；
2. 用嵌入模型（Embedding Model）把每个 chunk 变成一个向量；
3. 用户提问时，把问题也变成向量，用余弦相似度（Cosine Similarity）找最像的 Top-K。

问题在于：**向量检索本质是“双塔（Bi-Encoder）”**——问题和文档分别编码，彼此看不到对方。它快，但精度有限，容易把“字面像、语义偏”的内容排到前面。

**重排序器（Reranker）** 通常基于**交叉编码器（Cross-Encoder）**：把 query 和每个候选文档拼在一起送进同一个模型，让模型直接判断“这两段文字到底有多相关”。它慢，但准得多，所以只用在少量候选上。

---

## 2. 双塔 vs 交叉编码器

| 维度 | Bi-Encoder（双塔） | Cross-Encoder（交叉编码器） |
|------|------|------|
| 输入 | query、doc 分别编码 | query + doc 拼接后一起编码 |
| 速度 | 快，可预计算 | 慢，必须实时算 |
| 精度 | 一般 | 高 |
| 典型用途 | 召回（Recall） | 重排（Rerank） |

所以工程上的经典结构是：**用 Bi-Encoder 召回 Top-100，用 Cross-Encoder 重排取 Top-5。**

---

## 3. Reranker 的打分方式

Cross-Encoder 输出的是一个分数（logit 或概率），表示 query-doc 的相关性。常见做法：

- **分类式**：模型输出相关 / 不相关，用 logit 或 softmax 概率当分数；
- **回归式**：直接输出一个连续相关性分数；
- **生成式**：让大模型给 0~10 分，但贵且不稳定。

实践中，`sentence-transformers` 的 `CrossEncoder` 是最常用的轻量方案。

---

## 4. 工程接入的典型管道

```
用户 Query
   │
   ▼
[Embedding 召回]  → Top-100 候选
   │
   ▼
[Reranker 重排]   → Top-5 高分
   │
   ▼
[LLM 生成答案]
```

要点：
- 召回数量要足够大（如 50~200），否则重排无从发挥；
- 重排后只取很小的 K（如 3~10）喂给 LLM，控制上下文长度；
- Reranker 可以本地小模型，也可以调用 Cohere Rerank、BGE Reranker 等 API。

---

## 5. 最小可运行示例

下面用 `sentence-transformers` 演示：先用小模型做粗召回，再用 Cross-Encoder 重排。

```python
# pip install sentence-transformers
from sentence_transformers import SentenceTransformer, CrossEncoder, util

# 1) 双塔：用于召回
bi = SentenceTransformer("all-MiniLM-L6-v2")

# 2) 交叉编码器：用于重排
cross = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")

docs = [
    "猫喜欢晒太阳。",
    "Python 是一门编程语言。",
    "狗需要每天遛。",
    "太阳是一颗恒星。",
    "如何用 Python 读取 CSV 文件？",
]
query = "怎样在 Python 中处理表格数据？"

# Step 1: 向量召回 Top-3
q_emb = bi.encode(query, convert_to_tensor=True)
d_emb = bi.encode(docs, convert_to_tensor=True)
hits = util.semantic_search(q_emb, d_emb, top_k=3)[0]
candidates = [docs[h["corpus_id"]] for h in hits]
print("召回:", candidates)

# Step 2: Reranker 重排
pairs = [(query, d) for d in candidates]
scores = cross.predict(pairs)

ranked = sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)
print("重排后:")
for text, s in ranked:
    print(round(float(s), 4), text)
```

运行后你会看到：召回里可能混进了“太阳/狗”这类字面相近的句子，重排后真正相关的“Python 读取 CSV”会被顶到最前。

---

## 6. 什么时候该用 Reranker？

- 检索质量直接决定 RAG 答案质量；
- 候选数量不大（几十到几百），延迟可接受；
- 愿意用一点额外算力换明显精度提升。

反之，如果只是做海量初筛、对延迟极敏感，就先用双塔，不必上 Reranker。
