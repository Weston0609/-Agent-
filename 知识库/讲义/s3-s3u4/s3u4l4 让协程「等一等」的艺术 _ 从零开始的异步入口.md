## py.async.sleep

# py.async.sleep：让协程「等一等」的艺术

> **一句话直觉**：`asyncio.sleep()` 就像在餐厅里下单后不傻站着等厨师，而是先去做别的事，等菜好了再回来端走 —— 它让单线程的 Python 也能同时「照顾」多个任务。

前置知识：无。只需要你会写普通 Python 函数即可。

---

## 一、先搞清楚一个类比：同步睡眠 vs 异步睡眠

在普通 Python 里，我们要「等 1 秒」会写 `time.sleep(1)`。这 1 秒里，整个程序**卡死**：CPU 什么都不干，就盯着秒表。这叫 **同步阻塞（synchronous blocking）**。

而 `asyncio.sleep(1)` 是**异步非阻塞（asynchronous non-blocking）** 的：它会告诉事件循环（event loop）「我先挂起 1 秒」，然后事件循环就跑去执行别的任务。1 秒后，事件循环再把控制权还给这个协程（coroutine）。

**关键点**：两者都「等 1 秒」，但异步版本不浪费这 1 秒去干别的活。

---

## 二、最小可运行示例：Hello World

Python 官方文档给出的入门例子就用了 `asyncio.sleep`：

```python
import asyncio

async def main():
    print('Hello ...')
    await asyncio.sleep(1)   # 等待 1 秒，但让出控制权
    print('... World!')

asyncio.run(main())
```

三个新名词先记一下：
- `async def`：定义一个**协程函数**（coroutine function）。
- `await`：在协程内部**等待**另一个协程/可等待对象（awaitable）完成。
- `asyncio.run()`：启动事件循环、运行主协程、结束后关闭循环。它是**程序入口**，不要在协程内部再调用它。

---

## 三、`asyncio.sleep` 的参数与返回值

`asyncio.sleep(delay, result=None)` 有两个参数：

- `delay`：等待的秒数，可以是浮点数，也可以是 `0`（表示「让出控制权一次，马上回来」）。
- `result`：等待结束后返回的值。默认 `None`。

在官方推荐的 **asyncio REPL** 里尝试（终端执行 `python -m asyncio`）：

```python
>>> import asyncio
>>> await asyncio.sleep(10, result='hello')
'hello'
```

`delay=0` 是一个非常有用的技巧：它承诺「我让出一次，让事件循环跑别的协程」。

```python
import asyncio

async def worker(name):
    print(f'{name} 开始')
    await asyncio.sleep(0)      # 主动让出，让其他协程有机会执行
    print(f'{name} 让出后又回来')

async def main():
    await asyncio.gather(worker('A'), worker('B'))

asyncio.run(main())
```

## 四、真正的威力：并发多个「等待」

如果每个任务都要等 1 秒，同步写法 **3 秒**；异步并发写 **约 1 秒**。

```python
import asyncio, time

async def fetch(name, delay):
    await asyncio.sleep(delay)
    return f'{name} 完成（耗时 {delay}s）'

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(
        fetch('A', 1),
        fetch('B', 1),
        fetch('C', 1),
    )
    print(results)
    print(f'总耗时约 {time.perf_counter() - start:.2f}s')

asyncio.run(main())
```

运行结果约 1 秒出头，而不是 3 秒。这就是 `asyncio.sleep` 存在的意义：**模拟 IO 等待**（网络请求、数据库查询、文件读取），在此期间让其他协程继续工作。

---

## 五、它为什么适合「IO 密集」场景

`asyncio` 官方定位是「用 `async/await` 语法写并发代码」，特别适合 **IO-bound（IO 密集）** 的高层网络代码：

- 网络请求（HTTP、WebSocket）
- 数据库访问
- 子进程管理
- 队列分发任务

`asyncio.sleep` 是这一切的**最小可演示单元** —— 学会它，你就理解了整个协程调度的核心机制。

> ⚠️ 但请注意：`asyncio.sleep` 不会加速 CPU 密集任务（比如大数组计算）。CPU 密集型任务依然要靠多进程（multiprocessing）。

**任务**：写一个「模拟并发下载」的小脚本。

要求：
1. 定义一个协程 `download(name, seconds)`，用 `await asyncio.sleep(seconds)` 模拟下载耗时，下载完成后返回 `f'{name} 下载完成'`。
2. 在 `main()` 中用 `asyncio.gather` 同时「下载」5 个文件，每个耗时 0.5~2 秒不等。
3. 用 `time.perf_counter()` 打印总耗时，验证它**接近最大的单个耗时**，而不是所有耗时之和。
4. 额外挑战：再写一个同步版本（用 `time.sleep`），对比两者总耗时差异，并在注释中写下你的观察结论。

提示代码骨架：

```python
import asyncio, time

async def download(name, seconds):
    await asyncio.sleep(seconds)
    return f'{name} 下载完成'

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(
        download('file1', 0.5),
        download('file2', 1.0),
        # ... 补全 3 个

```

做完后，你会**亲手感受到**为什么异步在 IO 密集场景下效率更高。

```python
import asyncio
import time


async def fetch(name: str, delay: float) -> str:
    """模拟一次带延迟的异步 IO 任务。"""
    print(f'[start] {name} 开始，预计耗时 {delay}s')
    await asyncio.sleep(delay)  # 挂起当前协程，让事件循环调度其他协程
    return f'[done]  {name} 完成'


async def main() -> None:
    start = time.perf_counter()
    # 并发执行三个任务，而不是顺序等待
    results = await asyncio.gather(
        fetch('A', 1.0),
        fetch('B', 1.0),
        fetch('C', 1.0),
    )
    for line in results:
        print(line)
    print(f'总耗时约 {time.perf_counter() - start:.2f}s（远小于 3s）')


if __name__ == '__main__':
    asyncio.run(main())
```

## py.async.run

# py.async.run：从零开始的异步入口

## 一句话直觉

`asyncio.run()` 是 Python 异步世界的“启动按钮”：你写好一个 `async def` 协程（coroutine），它负责创建事件循环（event loop）、运行协程、结束后清理资源。

---

## 1. 为什么需要它：同步 vs 异步

普通 Python 代码是**同步（synchronous）**的：一次只做一件事。当程序等待网络、磁盘或数据库时，CPU 只能干等。

`asyncio` 用**协程（coroutine）**和 **async/await 语法**写并发代码。协程遇到 `await` 时可以暂停，把控制权交还给事件循环，让其他任务先跑。

`asyncio.run()` 就是启动这一切的入口：

```python
import asyncio

async def main():
    print('Hello ...')
    await asyncio.sleep(1)
    print('... World!')

asyncio.run(main())
```

**关键结论**：没有 `asyncio.run()`，你定义的协程不会自动执行；它只是“可等待对象（awaitable）”。

---

## 2. 协程、await 与事件循环

- **协程函数**：用 `async def` 定义的函数，调用它不会立即执行函数体，而是返回一个协程对象。
- **await**：暂停当前协程，等待另一个协程/可等待对象完成。
- **事件循环（event loop）**：调度协程的“引擎”。`asyncio.run()` 内部会创建它、运行主协程、最后关闭它。

```python
import asyncio

async def say(name, delay):
    await asyncio.sleep(delay)   # 模拟 I/O 等待
    print(f'{name} 完成，等待了 {delay} 秒')

async def main():
    # 顺序 await：总耗时约 2 秒
    await say('A', 1)
    await say('B', 1)

asyncio.run(main())
```

这段代码是**顺序等待**的：A 完成后才轮到 B。要真正并发，需要把任务交给事件循环同时调度。

---

## 3. 用 create_task 实现并发

`asyncio.create_task()` 把协程包装成**任务（Task）**，立即交给事件循环调度，然后主协程可以继续做别的事。

```python
import asyncio
import time

async def say(name, delay):
    await asyncio.sleep(delay)
    print(f'{name} 完成')

async def main():
    start = time.perf_counter()
    # 创建两个任务，让它们并发运行
    task1 = asyncio.create_task(say('A', 1))
    task2 = asyncio.create_task(say('B', 1))
    await task1
    await task2
    print(f'总耗时: {time.perf_counter() - start:.2f} 秒')

asyncio.run(main())
```

**关键结论**：并发不是“同时执行”，而是“等待 I/O 时切换任务”。总耗时约 1 秒，而不是 2 秒。

---

## 4. 并发多个任务：asyncio.gather

手写 `create_task` 加 `await` 很啰嗦。`asyncio.gather()` 可以一次等待多个可等待对象，并按顺序返回结果。

```python
import asyncio

async def fetch(name, delay):
    await asyncio.sleep(delay)
    return f'{name}: {delay}'

async def main():
    results = await asyncio.gather(
        fetch('用户A', 1),
        fetch('用户B', 2),
        fetch('用户C', 0.5),
    )
    print(results)  # 按传入顺序返回

asyncio.run(main())
```

`gather` 适合“一批互不依赖的 I/O 任务一起等”。

---

## 5. run 的边界：什么能传，什么不能传

`asyncio.run(coro)` 的参数必须是一个**协程对象**，不能是普通函数，也不能是已经运行中的事件循环里的协程。

```python
import asyncio

async def main():
    print('ok')

# 正确：传入协程对象
asyncio.run(main())

# 错误示例：传函数本身
# asyncio.run(main)   # TypeError: a coroutine was expected
```

**工程级要点**：

1. `asyncio.run()` 每次调用都会创建一个新的事件循环，适合作为程序入口。
2. 不要在已经运行的事件循环内部再调用 `asyncio.run()`，会报 `RuntimeError`。
3. 在 Jupyter / REPL 里，事件循环可能已经存在；可以用 `python -m asyncio` 进入异步 REPL，直接 `await`。
4. `asyncio.run()` 会等待主协程完成，并取消所有未完成的后台任务。

```python
import asyncio

async def child():
    try:
        await asyncio.sleep(10)
    except asyncio.CancelledError:
        print('child 被取消了')
        raise

async def main():
    asyncio.create_task(child())
    print('main 结束')

asyncio.run(main())
# 输出：main 结束，然后 child 被取消（如果没有被 await 完）
```

## 动手练习

写一个 `async def download_all()`，用 `asyncio.gather` 并发模拟下载 3 个文件：

- 文件 A 耗时 1 秒
- 文件 B 耗时 2 秒
- 文件 C 耗时 0.5 秒

要求：

1. 每个任务打印“开始下载 X”和“下载完成 X”。
2. 最后打印总耗时。
3. 用 `asyncio.run()` 启动。
4. 预期总耗时约 2 秒，而不是 3.5 秒。

提示：用 `asyncio.sleep(delay)` 模拟 I/O。

```python
import asyncio
import time

async def download(name: str, delay: float) -> str:
    print(f'开始下载 {name}')
    await asyncio.sleep(delay)  # 模拟 I/O 等待
    print(f'下载完成 {name}')
    return name

async def download_all():
    start = time.perf_counter()
    results = await asyncio.gather(
        download('A', 1.0),
        download('B', 2.0),
        download('C', 0.5),
    )
    elapsed = time.perf_counter() - start
    print('结果:', results)
    print(f'总耗时: {elapsed:.2f} 秒')

if __name__ == '__main__':
    asyncio.run(download_all())
```
