# 第五章 API 怎么调：从 curl 到生产级封装

很多人卡在「我知道要调 API，但具体怎么调、参数怎么填、错了怎么看」。这一章把所有调用形态给全，照着抄就能跑。

## 5.1 最原始形态：curl

任何 SDK 都是对 HTTP 的封装。看懂 curl，你就永远不会被 SDK 卡住。

```bash
curl https://api.deepseek.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  -d '{
    "model": "deepseek-chat",
    "messages": [
      {"role": "system", "content": "你是一个简洁的助手。"},
      {"role": "user", "content": "用一句话说明什么是 RAG。"}
    ],
    "temperature": 0.3,
    "max_tokens": 200,
    "stream": false
  }'
```

响应结构（记住路径 `choices[0].message.content`）：

```json
{
  "id": "chatcmpl-xxx",
  "object": "chat.completion",
  "created": 1730000000,
  "model": "deepseek-chat",
  "choices": [
    {
      "index": 0,
      "message": {"role": "assistant", "content": "RAG 是先从外部知识库检索相关片段，再让模型基于这些片段作答的技术。"},
      "finish_reason": "stop"
    }
  ],
  "usage": {"prompt_tokens": 42, "completion_tokens": 38, "total_tokens": 80}
}
```

**`usage` 字段是你的账本**，生产环境必须记下来。

## 5.2 流式调用（用户感知的关键）

```bash
curl -N https://api.deepseek.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"写一首五言绝句"}],"stream":true}'
```

返回是 SSE 流：

```text
data: {"choices":[{"delta":{"role":"assistant","content":""}}]}
data: {"choices":[{"delta":{"content":"空"}}]}
data: {"choices":[{"delta":{"content":"山"}}]}
...
data: {"choices":[{"delta":{},"finish_reason":"stop"}],"usage":{...}}
data: [DONE]
```

Python 正确解析（**注意 `delta` 可能没有 `content` 字段**）：

```python
import json, httpx

def stream_chat(prompt: str, url: str, key: str, model: str):
    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}],
        "stream": True,
    }
    with httpx.stream("POST", url, json=payload, timeout=120,
                      headers={"Authorization": f"Bearer {key}"}) as r:
        r.raise_for_status()
        for line in r.iter_lines():
            if not line or not line.startswith("data: "):
                continue
            data = line[6:]
            if data == "[DONE]":
                break
            chunk = json.loads(data)
            delta = chunk["choices"][0].get("delta", {})
            if "content" in delta and delta["content"]:
                yield delta["content"]
```

**流式的三个坑**：
1. 代理（Nginx）默认缓冲响应，必须设 `proxy_buffering off;` 和 `X-Accel-Buffering: no`，否则用户等半天才一次性出字。
2. 必须设超时（`read timeout`），否则模型卡住时你的连接永远挂着。
3. 客户端断开时要主动终止上游请求，否则白烧 token。

## 5.3 工具调用（Function Calling）的完整流程

这是 Agent 的技术核心，必须手写一遍才懂。

```python
import json
from openai import OpenAI

client = OpenAI(api_key="sk-xxx", base_url="https://api.deepseek.com/v1")

tools = [{
    "type": "function",
    "function": {
        "name": "query_order",
        "description": "根据订单号查询订单状态。当用户询问物流、发货、退款进度时使用。",
        "parameters": {
            "type": "object",
            "properties": {
                "order_id": {"type": "string", "description": "订单号，形如 SO20240101"},
            },
            "required": ["order_id"],
        },
    },
}]

messages = [{"role": "user", "content": "帮我查下订单 SO20240101 到哪了"}]

# 第 1 轮：模型决定调工具
resp = client.chat.completions.create(model="deepseek-chat", messages=messages, tools=tools)
msg = resp.choices[0].message

if msg.tool_calls:
    messages.append(msg)                       # 必须把 assistant 的 tool_calls 原样放回
    for call in msg.tool_calls:
        args = json.loads(call.function.arguments)
        # 真实项目这里要：参数校验、权限校验、超时、异常捕获
        result = {"order_id": args["order_id"], "status": "已发货", "eta": "3 天"}
        messages.append({
            "role": "tool",
            "tool_call_id": call.id,           # 必须对应上，否则模型不认
            "content": json.dumps(result, ensure_ascii=False),
        })

    # 第 2 轮：模型基于工具结果回答
    resp2 = client.chat.completions.create(model="deepseek-chat", messages=messages, tools=tools)
    print(resp2.choices[0].message.content)
```

**五个必须做的防护**：

1. **`tool_call_id` 必须一一对应**，错一个就 400。
2. **参数必须校验**：模型会给出不存在的字段、错误类型、注入内容。用 Pydantic 校验。
3. **工具必须设超时**：外部 API 挂了不能让 Agent 卡死。
4. **工具结果必须限长**：返回 10 万字符的 JSON 会瞬间打爆上下文。截断 + 摘要。
5. **必须限制轮数**：`max_iterations` 之类，防止无限循环烧钱。

## 5.4 结构化输出（JSON Mode / Structured Outputs）

**目标**：让模型稳定输出可被程序解析的 JSON。

三种做法，可靠性递增：

```python
# 做法一：提示词约束（最不可靠，但兼容性最好）
prompt = """从文本中抽取信息，严格输出 JSON，不要任何解释：
{"name": "", "age": 0, "city": ""}
文本：张三，28 岁，住在杭州"""

# 做法二：response_format = json_object（模型保证是合法 JSON，但不保证 schema）
resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": prompt}],
    response_format={"type": "json_object"},
)

# 做法三：json_schema 严格模式（最强，支持的模型较少）
resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": prompt}],
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "person",
            "strict": True,
            "schema": {
                "type": "object",
                "properties": {
                    "name": {"type": "string"},
                    "age": {"type": "integer"},
                    "city": {"type": "string"},
                },
                "required": ["name", "age", "city"],
                "additionalProperties": False,
            },
        },
    },
)
```

**生产必做**：不管用哪种，都要 Pydantic 校验 + 失败重试 + 最终降级。用 `instructor` 库可以一行搞定：

```python
import instructor
from pydantic import BaseModel

class Person(BaseModel):
    name: str
    age: int
    city: str

client = instructor.from_openai(OpenAI(base_url="https://api.deepseek.com/v1", api_key="sk-xxx"))
person = client.chat.completions.create(
    model="deepseek-chat",
    response_model=Person,
    messages=[{"role": "user", "content": "张三，28 岁，杭州"}],
    max_retries=3,
)
print(person.name, person.age)
```

## 5.5 生产级封装：一个能上线的 LLM 客户端

裸调 SDK 上线一定出事。下面这个封装覆盖了重试、超时、限流、计费、日志五件事。

```python
import time, random, logging, json
from dataclasses import dataclass
from openai import OpenAI, APIError, RateLimitError, APITimeoutError

log = logging.getLogger("llm")

@dataclass
class LLMConfig:
    base_url: str
    api_key: str
    model: str
    timeout: float = 60.0
    max_retries: int = 3
    price_in: float = 0.0      # 元 / 百万 token
    price_out: float = 0.0

class LLMClient:
    def __init__(self, cfg: LLMConfig):
        self.cfg = cfg
        self.client = OpenAI(base_url=cfg.base_url, api_key=cfg.api_key,
                             timeout=cfg.timeout, max_retries=0)  # 重试自己控

    def chat(self, messages, tools=None, temperature=0.3, max_tokens=2048,
             response_format=None, trace_id: str = "") -> dict:
        last_err = None
        for attempt in range(self.cfg.max_retries):
            try:
                t0 = time.time()
                resp = self.client.chat.completions.create(
                    model=self.cfg.model,
                    messages=messages,
                    tools=tools,
                    temperature=temperature,
                    max_tokens=max_tokens,
                    response_format=response_format,
                )
                latency = time.time() - t0
                usage = resp.usage
                cost = (usage.prompt_tokens * self.cfg.price_in
                        + usage.completion_tokens * self.cfg.price_out) / 1e6
                log.info(json.dumps({
                    "event": "llm_call", "trace_id": trace_id, "model": self.cfg.model,
                    "latency_s": round(latency, 2),
                    "prompt_tokens": usage.prompt_tokens,
                    "completion_tokens": usage.completion_tokens,
                    "cost_cny": round(cost, 6),
                    "attempt": attempt + 1,
                }, ensure_ascii=False))
                return {
                    "message": resp.choices[0].message,
                    "usage": usage.model_dump(),
                    "cost": cost,
                }
            except RateLimitError as e:
                last_err = e
                sleep = min(2 ** attempt + random.random(), 30)   # 指数退避 + 抖动
                log.warning("rate limited, retry in %.1fs", sleep)
                time.sleep(sleep)
            except APITimeoutError as e:
                last_err = e
                log.warning("timeout, attempt %d", attempt + 1)
            except APIError as e:
                last_err = e
                if e.status_code and 400 <= e.status_code < 500 and e.status_code != 429:
                    raise                                          # 客户端错误重试无用
                time.sleep(2 ** attempt)
        raise RuntimeError(f"LLM call failed after {self.cfg.max_retries} retries") from last_err
```

**为什么必须自己写重试**：SDK 自带的重试不区分错误类型，会把 400 参数错误也重试三遍，浪费时间和配额。而且它不会记录成本。

## 5.8 自己写一个 MCP Server（从零到上线）

这是本章的重点。下面给两个版本：**最小可运行版**和**生产可用版**。

### 5.8.1 最小版（30 行，stdio 传输）

```python
# server.py
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo-tools")

@mcp.tool()
def add(a: int, b: int) -> int:
    """两数相加。当用户需要做加法计算时使用。"""

@mcp.resource("config://app")
def get_config() -> str:
    """返回应用配置。"""
    return '{"env": "dev", "version": "1.0"}'

if __name__ == "__main__":
    mcp.run(transport="stdio")
```


### 5.8.2 生产版：带鉴权、校验、超时、审计的业务 Server

```python
# order_server.py —— 暴露「订单查询」能力的 MCP Server
import json, logging, os, time
from datetime import datetime
from typing import Literal

from mcp.server.fastmcp import FastMCP, Context
from pydantic import BaseModel, Field

logging.basicConfig(level=logging.INFO,
                    format='{"ts":"%(asctime)s","level":"%(levelname)s","msg":"%(message)s"}')
log = logging.getLogger("order-mcp")

mcp = FastMCP("order-service", host="0.0.0.0", port=8090)

# ---------- 数据模型：入参和出参都必须强类型 ----------
class OrderQuery(BaseModel):
    order_id: str = Field(pattern=r"^SO\d{8}$", description="订单号，形如 SO20240101")

class OrderInfo(BaseModel):
    order_id: str
    status: Literal["待付款", "已付款", "已发货", "已签收", "已取消"]
    amount: float
    created_at: str
    tracking_no: str | None = None

# ---------- 模拟数据库 ----------
_FAKE_DB = {
    "SO20240101": {"status": "已发货", "amount": 299.0,
                   "created_at": "2024-01-01T10:00:00", "tracking_no": "SF1234567890"},
}

def _auth_check(ctx: Context) -> str:
    """从请求元数据里取调用方身份。MCP 2026 规范下，身份放在 _meta 里。"""
    tenant = None
    try:
        meta = ctx.request_context.meta or {}
        tenant = meta.get("tenant_id")
    except Exception:
        pass
    if not tenant:
        # 生产环境这里要抛错；本地开发给个默认值
        tenant = os.getenv("MCP_DEFAULT_TENANT", "demo")
    return tenant

@mcp.tool()
async def query_order(params: OrderQuery, ctx: Context) -> str:
    """根据订单号查询订单详情。

    何时使用：用户询问某个订单的状态、金额、物流单号时。
    何时不用：用户没有提供订单号时，应先追问。
    返回：JSON 字符串，字段见 OrderInfo。
    """
    tenant = _auth_check(ctx)
    t0 = time.time()

    row = _FAKE_DB.get(params.order_id)
    if row is None:
        log.info(json.dumps({"event": "order_not_found", "tenant": tenant,
                             "order_id": params.order_id}, ensure_ascii=False))
        return json.dumps({"error": "订单不存在", "order_id": params.order_id},
                          ensure_ascii=False)

    info = OrderInfo(order_id=params.order_id, **row)
    log.info(json.dumps({
        "event": "query_order", "tenant": tenant, "order_id": params.order_id,
        "latency_ms": round((time.time() - t0) * 1000, 1),
    }, ensure_ascii=False))
    return info.model_dump_json()

@mcp.tool()
async def refund_order(order_id: str, amount: float, reason: str, ctx: Context) -> str:
    """对订单发起退款。

    危险操作：金额超过 500 元或订单已签收超过 7 天时，必须走人工审核，
    本工具会直接拒绝并提示转人工。
    """
    tenant = _auth_check(ctx)
    if amount > 500:
        return json.dumps({"error": "金额超过 500 元，需人工审核", "action": "escalate"},
                          ensure_ascii=False)
    log.info(json.dumps({"event": "refund", "tenant": tenant, "order_id": order_id,
                         "amount": amount, "reason": reason}, ensure_ascii=False))
    return json.dumps({"ok": True, "refund_id": f"RF{int(time.time())}"}, ensure_ascii=False)

@mcp.resource("order://schema")
def order_schema() -> str:
    """订单数据字典，供模型理解字段含义。"""
    return json.dumps(OrderInfo.model_json_schema(), ensure_ascii=False, indent=2)

@mcp.prompt()
def refund_checklist(order_id: str) -> str:
    """退款审核清单模板。"""
    return f"""请审核订单 {order_id} 的退款申请，逐项确认：
1. 订单是否在退款期内（签收 7 天内）
2. 金额是否与订单金额一致
3. 是否有重复退款记录
4. 是否需要人工审批
输出格式：每项一行，结论用「通过/不通过/需人工」。"""

if __name__ == "__main__":
    # 远程部署用 streamable-http；本地集成用 stdio
    mcp.run(transport="streamable-http")
```

### 5.8.3 写 MCP Server 的七条铁律

1. **工具描述就是 Prompt**。写清「何时用、何时不用、返回什么」。模型只能靠这段文字决策。好的描述能让选对率从 60% 提到 95%。
2. **参数用 Pydantic 强类型 + 约束**（正则、枚举、范围）。模型会给出离谱参数，schema 是第一道防线。
3. **工具粒度要适中**。太细（`get_user_name`、`get_user_age`）导致调用次数爆炸；太粗（`do_everything`）导致参数难填。**一个工具 = 一个业务动作**。
4. **返回值必须限长且结构化**。用 JSON，别返回大段自然语言。列表默认截断到 20 条，并告诉模型「还有更多，请缩小范围」。
5. **危险操作必须内置闸门**。转账、删除、发邮件这类工具，在**工具内部**做金额/权限校验，不要指望提示词约束模型。
6. **必须记审计日志**。谁（tenant/user）、什么时候、调了什么、参数是什么、结果如何。这是合规要求，也是排障依据。
7. **错误要可读**。「订单不存在」比 `KeyError: 'SO20240101'` 有用一万倍——模型能据此调整策略。

### 5.8.4 MCP 的常见误用

| 误用 | 后果 | 正确做法 |
| --- | --- | --- |
| 把整个数据库 CRUD 暴露成 20 个工具 | 模型选错，且无权限控制 | 只暴露业务动作，如 `query_order` |
| 工具返回原始 SQL 结果集 | 上下文爆炸 | 聚合 + 限行 + 摘要 |
| 用 MCP 传大文件 | 上下文和带宽双爆 | 传引用（URL/ID），让工具自己去取 |
| 每个微服务一个 MCP Server | 客户端要连 20 个 | 按业务域聚合，一个域一个 Server |
| 不做版本管理 | 改工具签名导致线上 Agent 崩 | 工具名带版本或用 `server/discover` 宣告能力 |

## 5.9 模型上下文窗口的实操计算

上线前必须算清楚，否则一定在线上炸。

```text
可用输入预算 = 模型上下文上限 − 输出预留 − 系统提示 − 工具定义 − 安全余量

例：128K 上下文
  输出预留      8192
  系统提示      1500
  工具定义 8 个  2400
  安全余量      2000
  ─────────────────────
  可用输入     117,908 token  ≈ 约 8 万汉字
```

**但这只是「物理上限」，不是「有效上限」**。实测表明多数模型在超过 30%～50% 窗口后，中间内容的召回率显著下降。工程上应该：

- 单轮输入控制在 **8K～16K** 以内（大多数任务足够）。
- 超长文档用「分块摘要 + 层级汇总」而不是硬塞。
- 历史对话超过 20 轮就压缩成摘要。
- 工具返回永远截断。

## 5.10 一份可直接用的 API 调试清单

调不通时，按这个顺序查，90% 的问题三分钟内定位：

| 症状 | 优先检查 |
| --- | --- |
| 401 / 403 | Key 是否过期、是否带 `Bearer ` 前缀、base_url 是否少了 `/v1` |
| 404 | 路径错（`/v1/chat/completions` vs `/chat/completions`）、模型名错 |
| 400 invalid_request | 消息角色顺序错（tool 消息前必须有 assistant tool_calls）、`tool_call_id` 不匹配 |
| 429 | 触发 RPM/TPM 限制，需要退避或换 key |
| 500 / 502 | 上游服务异常，看厂商状态页 |
| 空响应 / 截断 | `max_tokens` 太小、`finish_reason=length` |
| 流式不出字 | 代理缓冲未关闭、未加 `stream: true`、前端未逐块渲染 |
| 中文乱码 | 未设 `ensure_ascii=False`（Python）或 Content-Type 非 UTF-8 |
| 工具不触发 | 工具描述太模糊、模型不支持 function calling、`tools` 未传 |
| 结果不稳定 | temperature 太高、缺 few-shot 示例、schema 未约束 |
