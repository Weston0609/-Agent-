# 前言：这本书解决什么问题

## 写给谁

这本书写给三类人。

| 你是 | 典型身份 | 本书给你的 |
| --- | --- | --- |
| 不会写代码，但要用 AI 做成事 | 产品经理、运营、业务负责人、创业者 | 从需求到上线的完整方法，不写代码也能落地 |
| 刚入行的工程师 | 会调 API，说不清原理，选型靠搜 | 原理、调用、选型、排错的可复用判断框架 |
| 团队技术负责人 | 要定方案、要保证不出事、要为结果负责 | 架构、成本、安全、抗淘汰的决策依据 |

## 解决什么问题

市面上讲 AI 的资料有两类毛病：

- **只讲概念**：Transformer、注意力机制讲得很漂亮，但你依然不知道明天上班该干什么。
- **只讲操作**：三步搭一个 RAG、五行代码接个大模型，但换个场景就废，出了问题查不出来。

这本书试图补上中间那段：**从原理到调用、从选型到踩坑、从部署到变现的完整链条**。每一章都回答三个问题：它是什么（原理）、怎么用（调用）、什么时候别用（边界）。

## 体例说明

- **表格优先**：能用表格说清的不用段落，方便对比和查阅。
- **代码可直接跑**：示例默认 Python 3.11，尽量零依赖或只用最少的库。
- **标注边界**：每个方案都写「什么情况下别用」，这比写优点更有价值。
- **不回避钱**：成本数字都给了计算过程，你可以按自己的情况重算。

## 一个提醒

技术变化很快。本书的原则、架构思路、排错方法在几年内都成立；但**具体的版本号、价格、参数名会过时**。遇到对不上的地方，以官方文档为准，然后把差异记下来——这个习惯本身就是工程师的核心能力。

> 读完不等于会。每章末尾的自检清单，答不上来的就回去重读。真正让你进步的不是「看过」，是「做过一次并踩过坑」。
